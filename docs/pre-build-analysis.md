# 编译前分析模板

实际适配开始构建前，在编译仓根保存 `ADAPTATION_ANALYSIS.md`；用户指定名称优先。按现有证据填写，未知明确标记，不为填表先运行构建。静态扫描是候选清单，不代替源码调用关系。

```markdown
# <组件> HCU 适配分析

| 基线 | 当前值/证据 |
| --- | --- |
| 仓库、源码绝对路径 | ... |
| 用户要求的 ref / 实际 branch、HEAD、dirty | ... |
| 新适配分支 / 已确认恢复分支 | ... |
| 节点、容器、系统、DTK/编译器、gfx/wave | ... |
| Python/框架/依赖版本与实际路径 | ... |
| 必需功能、原测试、性能/集成约定 | ... |

## 构建与选路

| target | 原构建入口与证据 | 原生路径状态 | 选用路线及原因 | 计划命令/工作目录 |
| --- | --- | --- | --- | --- |
| ... | ... | available/unknown/unavailable | ... | ... |

## 依赖与代码差异

拟修改接口/协议可用以下精简记录：位置 → 原问题/失败证据 → 目标库能否直接满足（owner、版本、重载）→ 最小改法 → 验证入口。涉及组宽时补 W/G/L、mask 消费者、grid/stride、边界条件；与该接口无关的字段不必填写。

| 位置/依赖 | 原问题/失败依据 | 目标owner、版本/重载与可复用性 | 最小处理方案 | 验证入口 | 必需/批准排除/待核实 |
| --- | --- | --- | --- | --- | --- |
| ... | 编译不支持/行为错误/可选整理，附依据 | 头文件/库、实际编译条件；可复用/真实缺口/未知 | ... | 原用例或边界输入 | ... |

## 验证计划与未决项

| 范围 | 原测试入口与原断言 | 数据/设备条件 | 计划步骤或阻塞 |
| --- | --- | --- | --- |
| ... | ... | ... | ... |

执行前需补充：...
```

含 CUDA 输入的目标默认转码。记录可复用的 HIPIFY 链、转换器能力、原始根、生成根、映射和预计写集。纯 HIP 目标沿原生入口构建；选择不转码时写明用户的显式要求。依赖排除须有批准来源。

涉及PyTorch接口转换时，再记实际转换器模块/commit/代际、构建Python、最终映射与目标Torch的header/namespace对应关系；保留一个stream/guard/allocator加runtime的前后转换样例。格式与判别见[HIPIFY v1/v2案例](../references/pytorch-hipify.md)，不以Torch版本号单独决定全部映射。
